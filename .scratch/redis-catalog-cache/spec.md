## 目标与权威说明

让 Redis 缓存三类医疗目录，减少重复 SQL，并保证缓存故障时目录与管理操作可用。完整行为、代码入口、参数、故障语义和 R01～R15 验收标准统一维护在[实施方案](../../docs/redis-catalog-cache-design.md)，任务顺序见[地图](map.md)。

## 已确认的决定

| 问题 | 用户确认 |
| --- | --- |
| Q1 首期范围 | 只完整设计医院、科室、医生目录缓存；限流下一阶段 |
| Q2 更新时效 | 接受分钟级短暂旧资料；管理员结果和预约创建以 MySQL 为准 |
| Q3 部署目标 | 单实例落地，兼容两个实例共享 Redis；暂不做集群或多级缓存 |
| Q4 故障策略 | 优先可用，Redis 故障回源；数据库已提交而缓存失效失败仍返回成功 |
| Q5 默认 TTL | 医院/科室5分钟，医生2分钟，空列表30秒，可配置且读取不续期 |
| Q6 完成标准 | SQL 减少、提交失效、回滚隔离、故障回源、跨实例、环境隔离及原业务回归；不承诺无基线的性能百分比 |
| Q7 共同理解 | 确认本次只落方案和任务，标明设计已确认、代码未实施；事务内查询绕过缓存，场次缓存/JWT撤销暂缓 |

无待用户回答的设计问题。常规实现选择已在方案中给出；实施发现改变上述业务承诺的约束时，再提出具体差异。
