## 目标

对最终消息结构和接口做一次真实依赖验证，补齐既有测试只模拟重复、尚未直接覆盖的事务故障窗口。前序已有聚焦测试失败必须原任务解决，不以本任务集中掩盖。

## 必须保留的已有证据

- Outbox 在 Broker 停机时保留、恢复后发布；return 耗尽 FAILED；SKIP LOCKED 并发领取。
- 真实验签回调在 Broker 不可用时仍可提交资金/Outbox。
- 业务写入后提交前故障一起回滚，重试可成功。
- 业务提交后 ACK 丢失触发真实重投，Inbox/库存/序号不重复。
- 截止边界与已关闭预约的退款补偿。
- 退款父锁先于子锁、渠道调用期间不持有数据库事务、慢失败不覆盖成功。

## 重点补齐

1. **S12**：通过测试代理/装饰器在 Broker 收到原消息后、数据库 markPublished 或事务提交时制造故障。断言 DB 未标发布，再次执行会重发原 ID/正文；接入真实消费者后库存/序号/Inbox 只产生一次效果。现有手工发布两次的测试不能单独充当这一证据。
2. **S23**：退款失败消息必须通过新严格 Codec 并进入渠道，检查确实三次调用及 TTL 间隔，正确写失败事实后进入 DLQ；防止“提前拒绝也看到 DLQ”的假通过。
3. **S24**：渠道已按 refundNo 成功后，本地 complete 落库失败；再次执行相同 refundNo，幂等渠道只产生一笔退款结果，本地最终成功。无需真实支付渠道，但必须明确使用的幂等渠道替身。
4. 两消费路径和重放对转发不确定、ACK/NACK 异常和原消息保留有直接断言。

故障注入仅在测试源码，不能增加生产故障开关或运维业务 API。Mock 只能用于制造窗口/外部响应，不能把需验证的真实数据库事务或 Rabbit 路由整个替换掉。

```bash
./mvnw -Pmysql-it verify
./mvnw -Preliability-it verify
```
