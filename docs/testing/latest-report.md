## 同步支付验收

| 场景 | 实测结果 |
| --- | --- |
| 四个固定场次的时间边界 | 场次下单截止前一秒可下单，截止当秒拒绝。订单最晚支付当秒仍可付款，过期扫描跳过该单。超过最晚支付时间时，接口拒绝支付 |
| 支付事务与重复请求 | 并发付款只确认一次，重复请求保留支付时间和就诊序号。注入确认写入异常后，支付、预约和库存一起回滚，可重试 |
| 取消与付款、过期 | 付款和取消并发只有一个动作成功。付款前取消或到期回收暂占，已确认预约拒绝自助取消 |
| 隔离 demo 与 RabbitMQ 启动 | 先停隔离 RabbitMQ，再用启动脚本拉起并等待健康。通过 Vite 代理运行下单、同步支付、重复支付和取消，RabbitMQ 在业务流程前后均健康，demo vhost 无队列，Broker 无 AMQP 连接 |

## 预约占号验收

| 场景 | 实测结果 |
| --- | --- |
| 同一医生同一天的两个场次各自占号 | 两个场次已存在或均需首次生成时，暂停 08:00–10:00 订单提交，10:30–12:00 的订单先提交成功。解除暂停后，每场各暂占一个号 |
| 同场次并发首次预约或争抢最后一个号 | 同场次只生成一条库存记录。已有或首次生成的场次只有一个名额时，只成功一单 |
| 预约规则回归 | 同键重放、跨账号同证件防重、锁后到达截止、建单失败回滚及费用快照用例通过 |

## 2026-11-18 三环境人工验收

该轮在独立源码副本和全新 Compose 数据卷上进行，使用真实 MySQL、Redis、RabbitMQ 和 Mailpit。运行应用的端口为前端 5173 和后端 8080。

| 场景 | 实测结果 |
| --- | --- |
| 首次启动与默认配置 | 完成 `init` 和 `npm ci` 后，无参数的 `start` 进入 demo，前后端就绪标识匹配，网页可访问。单独直接运行 JAR 也默认进入 demo，监听 8080。 |
| 脚本与 JAR 并发 | 第二个脚本在第一个启动途中被拒绝。暂停已持锁、尚未监听的 dev JAR 后尝试启动 demo JAR，demo 被拒绝，演示库中的就诊人记录保留。 |
| 切换与进程归属 | 实测 demo → dev → test → demo，浏览器地址始终为 5173。仅剩 dev 前端时，脚本和直接启动 JAR 都拒绝启动另一环境。停止整套后可继续切换。Vite 拒绝覆盖固定地址、端口或关闭严格端口检查。 |
| 前端失败恢复 | 注入不匹配的 Vite 代理目标，前端启动失败后，本次后端退出、托管记录清理。恢复配置后同环境启动成功。 |
| 数据与维护命令 | dev/test 普通重启保留新增记录。demo 重启清除演示记录并使旧 JWT 失效。test 调时可查询、设置和恢复。整套停机后执行 `reset test`，结果仅影响 test。 |
| 页面环境与会话隔离 | Chrome 保留原 demo 标签页后切到 test，旧页面请求收到 409 / 1003，刷新后未加载 demo 登录或草稿。Vitest 验证会话和草稿按环境隔离。 |
| demo 业务链路 | 直接启动 JAR 选择 demo，手动启动不匹配的 test 前端被拒绝。通过 Vite 代理完成挂号、MockPay 付款、到院签到、开始接诊和完成接诊。Chrome 页面显示已就诊。 |

demo 的预约和接诊时段通过临时调整隔离验收 JVM 的时钟覆盖。业务操作通过真实 HTTP 执行，Chrome 核验登录、最后的就诊页面和环境切换。本轮覆盖本地脚本和 JAR 入口。更早的邮箱注册、医生账号权限和预约主流程验收见[历史记录](../history.md)。
