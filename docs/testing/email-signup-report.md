每环境均通过真实页面发送邮件，打开Mailpit收件页面并通过其API读取邮件验证码，在前端完成验证邮箱和设置密码，跳转登录页后实际登录，调用users/me确认邮箱及USER角色。浏览器为本机Chromium 156，Playwright控制；截图及脱敏步骤记录保存在 `.scratch/email-signup/`，不纳入Git。

验证码过期在每环境均实际等待五分钟，保持默认300秒TTL，没有缩短TTL、修改Redis过期时间或调整业务Clock。其他错误分支使用真实HTTP请求检查3003、3004、3005和3001。重复邮箱既检查发送阶段，也在账号创建前取得两张票据，第一张注册成功后用第二张尝试注册，最终MySQL中该邮箱恰好一条。

数据库复核确认每环境两个正式验收邮箱各一条用户记录；仅验证码错误、过期和无效票据的邮箱均未创建用户。登录后的资料由真实接口读取。验收账号保留，密码、验证码、票据、Token均不写入本报告。

验收严格按test → stop并确认全部六个应用端口释放 → dev → stop并确认全部六个应用端口释放 → demo → stop执行。每个浏览器脚本也检查其他环境端口未运行。始终只有一套常驻前后端，临时MySQL测试容器不运行任何三环境应用。

test未reset，dev保留数据，demo按既有启动生命周期重建自身数据。未清空共享收件箱；Mailpit使用默认临时存储。验收结束后全部前后端与四个共享Compose服务均停止，恢复原停止状态；Mailpit容器保留由Compose管理，既有数据卷保留。
