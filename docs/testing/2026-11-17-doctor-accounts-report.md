## 真实环境验收顺序

初始三套前后端及共享Compose均停止。本轮启动共享MySQL、Redis、RabbitMQ后，依次执行：

1. 启动test，完成HTTP、MySQL比对和浏览器验收，通过后停止test。
2. 执行dev只读启动预检，启动dev并完成验收，通过后停止dev。
3. 启动demo，按既有生命周期重建demo自身数据，完成验收后停止demo。
4. 停止本轮启动的共享Compose容器，保留容器及数据卷，恢复初始停止状态。

各环境使用对应前后端和数据库，无同时运行两套前后端。test没有执行重置，dev没有执行重置或新增验收业务数据。demo重建数据及轮换JWT密钥是其既有启动行为。

## test补充分支

本轮仅在test创建临时注册用户和临时医生档案，用真实接口验证：

1. 普通注册用户访问管理查询返回403。
2. 新增未绑定医生仍出现在查询列表，账号ID和邮箱为null，状态为UNBOUND，提示“未绑定账号”。
3. 使用原首次绑定接口后重新查询，邮箱和账号ID立即更新，状态为BOUND，提示“使用注册时设置的密码”。
4. 绑定账号重新登录后获得DOCTOR角色。

临时医生通过管理员删除接口移除，临时用户及其角色关系按本次创建的准确ID清理。医生编号分配仍按现行规则保留已分配编号，不回退自增值。demo额外验证普通演示用户访问管理查询返回403。
