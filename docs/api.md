## 通用约定

业务 API 使用统一响应结构。独立的状态探测格式见[本地环境识别](#本地环境识别)。

```json
{ "code": 0, "message": "success", "data": {} }
```

注册、登录、用户头像读取和本地环境探测可免 Bearer Token。业务接口使用 Bearer Token，管理员接口同时要求 `ADMIN` 角色。

ID 在 JSON 中为字符串，容量、序号和 `expiresIn` 为数字。创建预约的 `amount` 和预约设置、场次的 `registrationFee` 为字符串，预约详情的 `amount` 为 JSON 数值。

日期使用 `yyyy-MM-dd`，时间使用 `HH:mm:ss`。业务时间按 `Asia/Shanghai` 解释，`LocalDateTime` 响应不带时区偏移。各接口的业务响应字段位于统一包装的 `data` 中，字段定义见 OpenAPI；错误时 `data=null`，详见[主要错误](#主要错误)。

## 账号注册、登录与当前用户

> OpenAPI：`Auth`、`User`。接口、字段、状态码和示例见[契约](openapi/README.md)。

注册流程为：发送六位数字验证码 → 校验验证码并取得一次性注册票据 → 提交票据完成注册。验证码保留前导零，验证码和注册票据默认各有效五分钟；重发覆盖旧验证码，验码成功后旧码被消费，提交注册时消费票据。

邮箱去除首尾空白并转小写；注册密码为 8–64 字符；注册成功授予 `USER`。登录返回 Bearer Token，默认有效期 7200 秒；角色变更后需重新登录以取得新权限。当前用户接口需要登录，返回本人信息和当前头像地址。

相关错误码：邮箱已注册 `409 / 3001`，验证码错误 `400 / 3003`，验证码过期 `400 / 3004`，注册票据无效 `400 / 3005`，登录失败 `401 / 2003`。

## 用户头像

> OpenAPI：`User`。接口、字段、状态码和示例见[契约](openapi/README.md)。

头像只操作当前登录账号，不需要客户端指定用户 ID。读取接口免登录，替换和删除需要 Bearer Token。

上传只接受 2 MB 以内的 JPEG、PNG 或 WebP。服务端按文件头判定格式，并校验 JPEG/PNG 的宽高不超过 4096 像素；SVG、GIF 和伪装文件返回 `400 / 3101`。缺少 `file` 字段返回 `400 / 1001`；multipart 请求体上限为 4 MB，超过时返回 `400 / 3101`；存储暂时不可用返回 `503 / 3102`。

设置头像后，用户对象的 `avatarUrl` 形如 `/api/v1/users/{id}/avatar?v={对象文件名}`，替换头像会改变 `v`。读取响应带长期 `Cache-Control` 和 `ETag`；请求携带匹配的 `If-None-Match` 时返回 `304`。头像按用户 ID 公开读取，不判断角色；知道用户 ID 即可查看，不建议上传敏感图片。删除头像后 `avatarUrl=null`，重复删除仍成功；旧对象在数据库更新成功后尽力删除。

## 就诊人管理

> OpenAPI：`Patient`。接口、字段、状态码和示例见[契约](openapi/README.md)。

所有接口只操作当前账号的就诊人，不接受客户端指定归属账号。就诊人 ID 与账号用户 ID 不同。新增就诊人初始启用。

创建时姓名、证件类型、证件号、联系电话、联系邮箱都必填且不能为纯空白；长度上限依次为 `64 / 32 / 32 / 32 / 120`。证件类型目前只支持 `RESIDENT_ID_CARD`，证件号去除首尾空白并转大写，校验 18 位格式、出生日期、部分编码及校验位；不进行外部实名认证。联系电话要求非空和长度合法，联系邮箱另校验格式并转小写。

资料修改中缺省或 `null` 字段保留原值，已填写字段须重新校验；状态修改需要布尔值 `enabled`。停用影响后续下单，已创建预约保留原有快照。响应只返回脱敏证件号，不返回证件号原文。

相关错误码：参数不合法 `400 / 1001`，访问他人就诊人 `403 / 2002`，资源不存在 `404 / 4001`，同账号重复登记证件 `409 / 4101`。

## 目录与场次

> OpenAPI：`Catalog`。接口、字段、状态码和示例见[契约](openapi/README.md)。

目录查询需要登录。父级医院或科室不存在、或者没有下级时，科室、医生数组为空；医生不存在时场次数组为空。

场次查询返回业务今天、明天、后天共 12 个场次，按日期和固定时段排列。`availability` 按 `STARTED`、`CUTOFF_REACHED`、`FULL`、`AVAILABLE` 的顺序判定；`bookable` 仅在 `AVAILABLE` 时为真。同一响应十二个场次共享 `serverTime`。[场次类型及其时间](business-flow.md#场次设置与库存)

场次查询依赖当前统一预约设置；设置记录缺失时返回 `500 / 1002`。

## 创建预约

> OpenAPI：`Appointment`。接口、字段、状态码和示例见[契约](openapi/README.md)。

已登录用户先领取预约令牌（默认 600 秒），创建预约时放入 `Idempotency-Key` 请求头。令牌作用于当前账号，比较内容为规范化后的医生、日期、场次类型和就诊人；同令牌同内容且原请求已完成时返回原回执，内容不同返回 `409 / 4103`，令牌无效或过期且未创建预约返回 `409 / 4104`。已取消或过期后重新预约须领取新令牌。

日期须在业务今天至后天内，且早于场次开始前 15 分钟；服务端确定金额、创建时间和支付截止。首次成功返回 `201`，幂等重放返回 `200`，原请求仍在提交返回 `202`。网络超时或 `503 / 5001` 时沿用原令牌和请求体重试。[下单幂等设计](booking-idempotency.md)

相关错误码：号源约满或场次不可用 `409 / 4002`，日期窗口或截止不符 `409 / 4202`，同场有效预约重复 `409 / 4204`，使用停用就诊人 `409 / 4102`，参数不合法 `400 / 1001`。

## 预约查询和生命周期

> OpenAPI：`Appointment`。接口、字段、状态码和示例见[契约](openapi/README.md)。

以下接口均要求登录，仅允许本人操作；预约不存在返回 `404 / 4001`，非本人返回 `403 / 2002`。列表默认按就诊日期、场次开始时间和预约 ID 降序，`order=ASC` 时改为升序。

`status` 是预约生命周期，`paymentStatus` 是支付单状态，`workflowStatus` 是组合展示状态；用户取消后 `workflowStatus=null`。`paymentExpired` 在预约已过期，或仍待支付且超过最晚支付时间时为真；后台关单前即可显示 `workflowStatus=EXPIRED`，而持久化 `status` 仍为 `PENDING_PAYMENT`。`canPay` 和 `canCancel` 只在待支付、支付单未付款且处于支付期限内时为真。详情包含创建时的就诊人、医生、科室和医院快照；证件号脱敏；`visit` 仅已确认预约非 null。

支付只允许待支付、支付单未付且未超过最晚支付时刻的预约；已过期返回 `409 / 4004`，其他不允许的状态返回 `409 / 4003`。重复支付已确认订单返回原支付时间和就诊序号。取消只允许关闭未支付的待支付预约；已取消或已过期的预约重复取消返回当前详情；已确认预约取消返回 `409 / 4003`。如果待支付预约已超时但尚未被后台关单，取消会按过期关闭并释放名额。[时间规则](business-flow.md#关键时间)

支付单关联缺失或不一致返回 `500 / 1002`。

## 到院签到与门诊接诊

> OpenAPI：`Visit`。接口、字段、状态码和示例见[契约](openapi/README.md)。

用户签到只能操作本人已确认且尚未签到的预约。签到开放时间为场次开始前 30 分钟，截止时间为场次结束时间；签到记录与「签到成功」通知在同一事务提交，成功后返回完整预约详情。重复或状态不符返回 `409 / 4502`，未到窗口返回 `409 / 4503`，已过截止返回 `409 / 4504`。

医生接口要求 `DOCTOR` 角色，只能操作本人已确认预约。场次概览按固定四场返回，省略 `date` 时使用业务今天，空场次补零；名单必须提供 `date` 和 `sessionType`，按就诊序号升序。医生详情只能读取本人已确认预约，不存在或不属于本人返回 `404 / 4001`。开始接诊只允许候诊中的预约，完成接诊只允许就诊中的预约；状态不符返回 `409 / 4502`，成功返回最新详情并写入对应通知。

用户详情的 `visit` 仅已确认预约非 null；无记录时推导 `NOT_CHECKED_IN`，签到后 `WAITING`，开始后 `IN_PROGRESS`，完成后 `COMPLETED`；未发生的时间为 null。`visit.canCheckIn` 表示查询时的签到资格，`checkInOpensAt`、`checkInClosesAt` 取自预约快照。[签到时间规则](business-flow.md#关键时间)

普通用户访问医生接口返回 `403 / 2002`；医生账号权限由[首次绑定](#首次绑定)授予。

## 消息中心

> OpenAPI：`Notification`。接口、字段、状态码和示例见[契约](openapi/README.md)。

以下接口要求登录，只读取当前账号自己的通知，不判断 `USER`、`DOCTOR` 或 `ADMIN` 角色。列表按 `occurredAt` 降序、`id` 降序排列，首版不分页；详情在列表字段外增加 `detail` 和 `appointmentId`，`detail` 是事件生成时保存的完整文案，后续修改就诊人或医疗目录不会改变。通知类型为预约成功、签到成功、开始接诊和完成接诊。

通知不存在或不属于当前账号时返回 `404 / 4001`，不区分两种情况。`appointmentId` 可用于跳转预约详情接口，预约归属校验继续生效。通知异步投递，刚完成业务操作后稍等或刷新列表即可看到。

## 管理员医院、科室与医生目录

> OpenAPI：`AdminCatalog`。接口、字段、状态码和示例见[契约](openapi/README.md)。

以下接口都要求登录且具有 `ADMIN` 角色；普通用户返回 `403 / 2002`。

医院名称、地址上限为 100、200 字符；科室名称上限为 100；医生姓名、职称、介绍上限为 64、64、500。提供的文本会去除首尾空白，非 null 的纯空白值被拒绝。创建医生可省略或传 null 的介绍；医生修改的 null 表示保留，不提供清空介绍或调整所属科室、医生编号的能力。

医生编号由系统生成，修改资料不改变编号。父级或目标资源不存在返回 `404 / 4001`；同医院科室名称重复返回 `409 / 4401`。医院仍有科室、科室仍有医生、医生仍有关联场次（包括历史场次）或数据库引用阻止删除时，返回 `409 / 4402`，不级联删除业务数据。

## 管理员统一预约设置

> OpenAPI：`BookingSettings`。接口、字段、状态码和示例见[契约](openapi/README.md)。

两个接口均要求 `ADMIN`。更新时容量和挂号费都必填：容量为正整数，费用最低 0.01 元，最多八位整数和两位小数；非法输入返回 `400 / 1001`。币种固定为 CNY。更新后用于后续新生成的场次，已存在的场次保留创建时的容量和费用快照。[设置生效范围](business-flow.md#场次设置与库存)

## 管理员医生账号

> OpenAPI：`DoctorAccount`。接口、字段、状态码和示例见[契约](openapi/README.md)。

### 管理员医生账号查询

查询要求 `ADMIN`，返回当前后端所连接环境的全部医生及实际账号绑定，按医院 ID、科室 ID、医生编号、医生 ID 排序。读取实际目录和绑定，不使用目录缓存；未绑定账号的医生也返回，无医生时 `items=[]`。`passwordHint` 只说明密码来源，不包含密码或密码哈希；预置医生的提示指向对应环境的 `LOCAL_SEED_PASSWORD`。[预置账号](environments.md#预置目录和账号)

### 首次绑定

首次绑定要求 `ADMIN`，同时授予账号 `DOCTOR` 角色，账号重新登录后即可使用医生接口。医生或账号已有绑定时返回 `409 / 4501`，包括对同一关系的重复绑定；当前接口只支持首次绑定。医生不存在返回 `404 / 4001`，请求缺少用户 ID 返回 `400 / 1001`。

## 本地环境识别

> OpenAPI：`LocalEnvironment`。接口、字段、状态码和示例见[契约](openapi/README.md)。

`GET /api/v1/local-environment` 在常驻环境提供无需登录的探测。后端接受流量时返回 200，已能响应请求且尚未就绪时返回 503；响应直接返回 `profile`、`ready` 和 `launchId`，不使用统一 `{ code, message, data }` 包装，并设置 `Cache-Control: no-store`。由 Python 脚本启动时 `launchId` 为当次启动标识；单独启动后端时通常为 `null`。

本地前端给 API 请求附带 `X-Appoint-Environment`。标识与正在运行的 profile 不匹配时返回 `409 / 1003`，提示刷新页面。直接调用 API 的客户端可省略此标识。

## test环境业务调时

> OpenAPI：`TestClock`。接口、字段、状态码和示例见[契约](openapi/README.md)。

调时接口在常驻 `test` 环境存在，需要 `ADMIN` 角色；其他环境不存在。提供查询、设置和恢复实时三个操作，响应包含 `businessTime` 和 `mode`（`realtime` 或 `adjusted`）。设置时使用带时区偏移的 ISO 时间字符串。

设置后业务时钟继续走秒；调时影响下单、支付、过期扫描和签到，并可能使已有待支付预约到期；回拨时间保留已提交的操作结果。Redis 有效期和 JWT 使用真实时间。后端重启或恢复实时后回到实时时钟。[调时操作和影响](environments.md#test-业务调时)
