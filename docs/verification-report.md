# 后端业务与真实 HTTP 验证报告

验证日期：2026-10-27（Asia/Shanghai）

## 交付范围

本轮验证医院预约后端闭环：注册登录、就诊人管理、目录查询、带就诊人快照及幂等键创建预约、凭证查询、模拟支付、取消、超时关闭和号源释放。所有 API 包装类型 `Long` ID 以字符串输出，避免 64 位订单号被调用方当作 JavaScript 数字处理时丢失精度；请求中的 `scheduleId`、`patientId` 兼容字符串和数字。

项目不包含业务前端。`business-flow-demo.html` 是独立的讲解文档，仅使用内置示例数据展示用户步骤和状态流转，不访问任何业务接口。

## 真实 HTTP 覆盖

`PatientJourneyHttpMySqlIT` 在随机 TCP 端口启动完整 Spring Boot 应用，并使用 Java HTTP Client 验证：

- 注册、重复邮箱、错误密码、登录、当前用户和无效 Token。
- 创建和选择就诊人，医院、科室、医生与号源查询，字符串 ID 和非法预约参数。
- 带 UUID 幂等键创建预约、列表、详情、跨用户越权和号源冲突。
- 模拟支付、重复支付、终态限制、取消、重复取消和释放后再次预约。
- 独立短支付期限下，真实定时任务关闭过期订单并释放号源。

`AppointmentLifecycleMySqlIT` 验证同键相同请求并发只创建一次、同键不同内容只有一个成功、同账号并发登记同一证件只有一条成功、就诊人修改与预约创建形成完整快照；同时继续验证两个用户竞争同一号源、支付与取消及支付与过期关闭后的三表终态一致。

H2 的 HTTP 验收还覆盖同键冲突、账号作用域、停用就诊人、失败后沿用原键重试、取消及资料变化后的首次响应重放、证件校验与脱敏、修改证件冲突和所有权检查。`InitialSchemaMigrationTest` 从独立空库执行唯一 V1，并验证第二次迁移不重复执行。

## 业务流程说明页

[交互式业务流程说明页](business-flow-demo.html) 提供以下纯本地互动：

- 在用户视角和系统视角之间切换预约步骤说明。
- 切换支付成功、主动取消和支付超时三种结局。
- 同时展示预约单、支付单和号源的对应状态。
- 展示创建就诊人、请求重试，以及历史凭证为何需要保存就诊人、联系方式、医院、科室、医生和时段快照。

页面源码没有网络请求、表单提交或业务 API 地址；刷新文件只会恢复内置演示状态。

## 业务边界

- 支付仅为后端模拟状态推进，没有金额和真实支付渠道。
- 没有管理后台、身份核验、退款、改签或已确认预约取消流程。
- 当前 Flyway 版本日志提示其声明的最高验证版本为 MySQL 8.1；本轮迁移和测试实际运行在 MySQL 8.4。
