# 中国医院与官方预约平台界面参考

调研日期：2026-11-14。目标：为 Vue 3 医院预约前端选择信息结构与预约交互，电脑端优先，兼容手机浏览器。本轮只做调研与设计建议，不编写前端代码。

## 证据范围

- 本文通过公开网页检索、打开页面及解析官方图片链接核对内容。没有登录真实患者账号、进入微信/App 内部，也没有提交预约。
- “公开页观察”指工具实际返回的页面文字、字段、链接或表格结构；不代表完整浏览器视觉验收。“官方教程”指发布方对操作的说明，不当作本次亲自操作所得。
- 本次未完成截图像素检查，故不判断当前网站的色值、字体、具体间距和响应式效果。下列图片地址用于后续人工查看，没有复制图片到仓库。旧教程只能证明其发布时的设计。
- 至少三个可访问官方来源已核实：北京协和医院、四川大学华西医院、北京市政府的 114 服务图解；另补充清华长庚医院官方教程、上海申康公开 H5。第三方挂号营销网站不纳入证据。

## 1. 北京协和医院：公开 PC 入口与出诊表

来源：[预约挂号公开页](https://www.pumch.cn/register.html)、[国际医疗出诊表](https://www.pumch.cn/department_ims/dsearchs/dockervisit/0/3.html)。均在本次成功打开。

**公开页观察：**预约页区分 APP、国际医疗部、银行卡预约；有疾病、科室、医师查询字段。出诊表按科室和上午/下午/晚上分行，以日期和星期分列，单元格列医生姓名，部分姓名是链接，空项用横线表示。观察到的是出诊信息，不能据此断言该医生仍有可预约余量。以上内容分别可在[预约页](https://www.pumch.cn/register.html)和[出诊表](https://www.pumch.cn/department_ims/dsearchs/dockervisit/0/3.html)核对。

**适用借鉴（设计推导）：**电脑端可保留日期与时段两个轴，方便比较；医院、科室、医生应有清晰上下文和搜索入口。本项目可缩为三日期×四场次，不需要一周大表。

**不适用：**不照搬国际医疗/银行卡渠道，也不将出诊姓名视为“可预约”按钮。公开页面不能证明已核验协和登录后的下单与支付界面。

## 2. 四川大学华西医院：患者入口与导诊分流

来源：[公众版首页](https://www.wchscu.cn/public/index.html)、[我不知道挂哪科](https://www.wchscu.cn/public/which.html)。均在本次成功打开。

**公开页观察：**公众首页列预约挂号、就诊指南、院区导航入口。分流页以“我不知道挂哪科”为题，提供疾病分诊和立即预约的入口；页面同时明示网站挂号系统升级，转公众号或华医通 App。这里只证实入口和告知内容，未核验疾病分诊运行结果及 App 交易页面。[首页](https://www.wchscu.cn/public/index.html)、[分流页](https://www.wchscu.cn/public/which.html)

**适用借鉴（设计推导）：**优先使用患者能理解的词；预约入口应明显。科室说明可以帮助选择，但需要已有数据支持，不能凭页面标题声称本项目具备智能导诊。

**不适用：**本项目希望电脑浏览器完成业务，不宜照搬扫码跳 App 的主流程；门户新闻、教学科研等栏目也不应占据预约工作区。

## 3. 北京 114：官方分步图解

**官方教程核验：**文章描述医院搜索、按科室选择、附近医院三种入口；演示医院→科室→日期及医师→时段→就诊人→核对并确认挂号。页面附各步骤图片。此处是对历史官方教程的概括，未登录现行 114 平台。[官方图解](https://www.beijing.gov.cn/fuwu/bmfw/bmjy/202109/t20210918_2496958.html)

**适用借鉴（设计推导）：**本项目有多医院，医院和科室选择不能被省略；下单前应汇总医生、日期、时段、就诊人、费用，避免替家人预约时选错人。电脑端可以合并展示步骤，不必复制移动端连续多屏。

**不适用：**不加入附近医院、定位、地图；图解中的确认成功不能替代本项目支付确认流程。

## 4. 北京清华长庚医院：用文字明确号源状态

来源：[《清华长庚微信公众号预约挂号&报告查询》](https://www.btch.edu.cn/xxdt/xwdt/54132.htm)，发布日期 2020-01-17，本次成功打开。

**官方教程核验：**支持从出诊信息查询或预约门诊进入；先找科室、医生，有号再选择就诊人。文章明确说明绿色“预约”代表仍有号源、红色“约满”代表该日期无号源。本次颜色结论来自官方文字说明，并非亲看现行截图。[官方教程](https://www.btch.edu.cn/xxdt/xwdt/54132.htm)

**适用借鉴（设计推导）：**场次状态要有文字，配色只做辅助；满额、截止、可预约应在选择前区分，不能都变成没有原因的灰色按钮。

**不适用：**历史教程中的短信验证、报告查询不在本项目当前范围，不应顺带新增。也不把这份 2020 年教程当作现行 UI 标准。

补充配图：[“预约/约满”说明后配图](https://www.btch.edu.cn/images/content/2020-01/20200117090135316778.jpg)。链接来自正文，本次图片抓取返回 Cache miss，未核验图片本体。

## 5. 上海申康：公开 H5 的多医院服务入口

来源：[上海申康医联 H5 首页](https://internethospital.shdc.org.cn/yilian-cloud-v2.0-wechat/src/index/index.html?type=1)，本次成功打开公开内容。

**公开页观察：**搜索占位文字包括医院、科室、医生；页面有健康卡、预约挂号、当日挂号、在线支付等入口，并显示关怀版可让文字更大更清晰的说明。只核验首页内容，未核验搜索结果、关怀版切换效果或挂号交易。[公开首页](https://internethospital.shdc.org.cn/yilian-cloud-v2.0-wechat/src/index/index.html?type=1)

**适用借鉴（设计推导）：**多医院搜索的对象应清楚；手机端优先清晰字号和易点击控件。可以把“我的预约”作为预约后的稳定返回入口。

**不适用：**不照搬整套服务九宫格；报告、在线问诊、候诊、影像等会超出已有能力。本项目三天窗口已包括今天，不需要为当日挂号再开一套流程。

## 本项目的设计取舍

以下为调研后的设计建议，尚未实现，也不声称是任一家医院的原样界面。

项目规则依据：[ADR 0005](../adr/0005-four-session-on-demand-booking.md)、[ADR 0007](../adr/0007-three-day-booking-and-session-cutoffs.md)、[ADR 0008](../adr/0008-visit-checkin-window.md)。预约窗口为今天、明天、后天，每天四场，共十二项；各场开始前十五分钟停止新下单。签到在现有窗口内处理。

| 场景 | 电脑端优先建议 | 手机浏览器适配 |
| --- | --- | --- |
| 找医院、科室、医生 | 保留面包屑与已选医院；列表提供已有数据支持的搜索/筛选 | 顺序选择，已选条件可回退修改 |
| 选择场次 | 三日期列×四固定时段行；展示时间、余量、费用和明确状态 | 三日期切换，当前日期下四个时段卡；保留明确日期与星期 |
| 确认下单 | 主区选择，旁侧展示预约摘要；核对就诊人后提交 | 单列摘要和明确确认按钮 |
| 支付及后续 | 将“待支付”和“已确认”分开；显示订单真实截止时间与已有操作 | 预约详情提供支付、取消及符合窗口时的签到入口 |
| 空结果与不可预约 | 保留当前条件并解释无结果、约满或已截止 | 同样保留条件，避免只给空白页 |

界面只呈现已有能力：不新增停诊、改约、病历处方、短信、地图/定位签到、自动叫号。简单签到入口不应包装成定位到院或排队系统。来源页面有这些服务，只说明其产品范围更大。
