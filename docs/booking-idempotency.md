# 预约下单幂等设计

账号用户在确认页提交一次预约后，如果浏览器未收到响应，可以在原页面再次点击「提交预约」。前端继续发送同一个令牌和同一份预约内容。已提交的重复请求返回首次下单的完整回执，场次只暂占一个名额。

## 令牌和提交

确认页向需要登录的 `POST /api/v1/appointments/token` 领取令牌。后端使用 `UUID.randomUUID()` 生成标准 UUID。接口返回 `token` 和 `expiresIn`（600 秒）。领取时只绑定账号，用户仍可在确认页改选就诊人。第一次点击提交前，前端将账号、令牌和当次请求体写入按环境隔离的 `sessionStorage`。`POST /api/v1/appointments` 继续用 `Idempotency-Key` 传令牌。

Redis 使用两条键，`<环境>` 和本地环境名一致。两个键的有效期均为真实时间，test 的业务调时只影响业务校验和支付时限。

| Redis 键 | 值 | 有效期 |
| --- | --- | --- |
| `appoint:<环境>:booking:token:<uuid>` | 发起账号 ID | 签发后 10 分钟 |
| `appoint:<环境>:booking:binding:<uuid>` | 账号 ID、请求摘要、预约单号 | 首次消费后 10 分钟 |

首次提交按医生、日期、规范化场次类型和就诊人计算 SHA-256 请求摘要。Lua 校验令牌归属，保存绑定并删除一次性令牌。重复调用可用绑定识别同一笔正在提交的预约，并校验账号和摘要。预约单号沿用 `AP` 加无连字符 UUID 的格式，Lua 首次消费时确定本次请求采用的编号，协调层把它交给预约暂占服务。不同账号提交同一个令牌时，接口按无效令牌处理。

## MySQL 事务和回执

`BookingCreationTransaction` 先登记 `appointment_create_requests`，再暂占场次名额、写预约单和有效占用、创建支付单，最后保存回执。整个流程属于同一个 MySQL 事务。

- `appointment_orders` 继续用 `UNIQUE (appointment_no)` 防止同一预约单号重复插入。
- `appointment_create_requests` 继续用 `UNIQUE (user_id, idempotency_key)` 约束同账号同令牌的登记。关联预约单 ID 和完整回执随建单事务提交。
- `response_json` 保存创建时的预约单 ID、预约单号、预约状态、支付单 ID、支付单号、支付状态、金额、币种、创建时间和最晚支付时间。`serverTime` 也是首次创建回执里的时间。支付页用预约单 ID 查询详情，以查询时的状态和服务端时间展示支付资格与倒计时。

## 创建接口判定顺序

1. 规范化令牌和请求内容，按账号与令牌读 MySQL 回执。同内容的已完成登记直接返回 `200` 和原回执，同键异内容返回 `409 / 4103`。
2. 尚无回执时执行 Lua。首次消费成功后启动 MySQL 创建事务，提交后返回 `201` 和完整回执。
3. 令牌已消费时，再查一次 MySQL，覆盖查回执与检查 Redis 之间事务提交的情况。已完成就返回原回执。仍有同内容绑定且尚无回执时返回 `202`，`data` 为 `{"pending":true}`。绑定内容不同返回 `409 / 4103`。两条 Redis 记录均不存在且 MySQL 尚无回执时返回 `409 / 4104`。
4. 场次截止、约满、就诊人停用等确定的业务拒绝随创建事务回滚。清除该请求的 Redis 绑定并返回原业务错误。用户明确收到业务失败后可以重新领令牌进行下一次提交。

首次 `201` 和重放 `200` 返回相同的成功 `data`。Redis 键过期后仍可按账号和令牌查已提交的快照。网络超时或 `202` 时前端保留原提交，留在确认页并允许再次点击「提交预约」。仅在收到完整成功回执后进入对应预约的支付页。

## 验收

在 test 环境拦截浏览器的第一次创建请求，先转发给后端并确认返回 `201`，再中止发给浏览器的响应。在原确认页再次点击「提交预约」，检查两次 POST 的 `Idempotency-Key` 和请求体一致，第二次返回 `200` 及原始预约、支付快照。数据库只有一张预约单、一张支付单、一份成功回执，号源只暂占一个名额。

自动化检查覆盖同键并发在提交前返回 `202`、提交后重放、同键不同预约内容、跨账号令牌、Redis 键移除后重放、业务拒绝后重新领取令牌，以及确认页在结果未知时复用原提交。真实 Redis 验证 Lua 和有效期，真实 MySQL 验证事务和库存。
