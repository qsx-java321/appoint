## 完整就诊主流程的具体走法

1. 管理员准备医生档案并绑定已注册账号；医生重新登录。用户另用一个浏览器窗口或浏览器配置文件登录，避免覆盖当前角色会话。
2. 用户在“就诊人”新增虚构资料，再到预约页面选医院、科室、医生、可预约场次和就诊人，核对后提交。
3. 在支付页点“发起模拟支付”，再点“模拟渠道成功”；等待显示“预约已确认 · 待签到”和就诊序号。渠道返回受理后，消息链路仍会继续确认预约。
4. 到签到窗口后在预约详情点击“到院签到”，看到“候诊中”。
5. 医生在工作台选同一日期及场次，查看名单和只读详情，点击“开始接诊”，用户刷新看到“就诊中”。
6. 医生点击“完成接诊”，双方刷新都显示“已就诊”；签到、开始、完成时间一致。完成接诊保留已确认名额及原就诊序号。

这里的“完成就诊”表示接诊进度完成；项目尚未实现病历、处方、药品收费和自动叫号。

## 时间相关流程怎样测试

四个场次是 08:00–10:00、10:30–12:00、14:00–16:00、16:30–18:00。下单只允许服务端今天至后天。

以当天 14:00–16:00 为例，创建预约须早于 13:45；首次签到允许在 **[13:30,16:00)**。13:29 签到拒绝，13:30 开放，16:00 首次签到拒绝。重复签到返回状态冲突，保留首次签到时间；超时未签继续待签到，不自动退款、释放库存或标记爽约。已签到记录允许医生跨日开始和完成接诊。

可以通过以下命令跳过等待；日期替换为自己本次测试的日期，`Z` 表示 UTC，例中对应上海 13:30：

```bash
python3 scripts/local_env.py clock test get
python3 scripts/local_env.py clock test set --instant 2026-11-15T05:30:00Z
python3 scripts/local_env.py clock test reset
```

设置后时间会继续走秒。每个分支另建订单；向前调时可能使其他待付款订单过期，回拨不会撤销已经完成的支付、过期、退款和就诊事实。结束后恢复实时。不要依赖 MockPay 跨后端重启继续查询旧交易和退款。
