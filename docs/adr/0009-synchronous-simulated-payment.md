# ADR 0009 同步模拟支付

## 决策

使用原有预约单与支付单。用户明确发起模拟支付时，在同一个 MySQL 事务内校验时限、登记支付、确认号源并分配序号。预约和支付依然作为各自模块的业务事实，协调模块复用场次 → 预约 → 支付单锁序。最晚支付时刻包含当秒，过期扫描采用严格晚于的边界。业务场景见[关键时间](../business-flow.md#关键时间)。

该方案取代 [ADR 0004](0004-independent-payment-and-reliable-events.md) 和 [ADR 0006](0006-late-payment-and-consumer-retries.md) 中的支付消息联动、渠道模拟、迟到退款和异步补偿。系统仅需演示支付操作，同库事务可以直接提供最终结果。RabbitMQ 继续随环境运行，保留通用 AMQP 配置。

## 升级后的历史数据

保留现有 Flyway 基线及历史支付表。已关闭或已退款的旧单仍可查，支付中的旧单可按未收款处理。过期扫描可恢复旧版在当时的支付截止前已收款但未确认的预约。切换前核对仍待确认的旧收款与未完成的旧退款，尤其是缺少支付时间或已经超过旧版支付期限的记录。继续在历史库中保留原有支付事实和审计资料。
