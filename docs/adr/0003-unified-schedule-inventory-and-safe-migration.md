# ADR 0003：医生排班使用统一库存与有效预约占用

`scheduleId` 自 V3 起标识一场上午或下午门诊，排班保存总量、可用、暂占、已确认和下一就诊序号；数据库检查库存恒等式，并以条件更新和排班行锁串行化同场竞争。有效预约另存一条占用记录，分别以“排班＋就诊人”和“排班＋规范化证件快照”建立唯一约束，从而在保留账号内就诊人关系的同时阻止跨账号重复预约。所有生命周期事务统一按排班、预约单、支付单顺序加锁，避免支付、取消、超时和停诊之间形成循环等待。

V2 在任何 DDL 前检查旧单号源是否仍有关联的待支付或已确认订单，存在时阻断迁移；V3 只增加列、表、约束和新演示排班，保留旧排班、终态订单和历史快照。旧排班的 `session_type` 为空，因此继续可读但不进入新预约目录，也不参与新库存生命周期。此选择避免清库或改写历史数据，代价是旧模型记录长期以只读兼容形态存在。
