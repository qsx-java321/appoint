# ADR 0008：签到采用预约快照时间窗口

状态：已接受，2026-11-13。替代原就诊日00:00至次日00:00的首次签到规则；预约下单和支付期限仍按[ADR0007](0007-three-day-booking-and-session-cutoffs.md)。

## 背景与决策

用户体验注册、预约、支付、签到和接诊闭环时，发现下午场上午及场次结束后均可首次签到的规则过宽。改为上海业务时间、现有秒精度：开放时间为预约日期与开始时间快照减30分钟，截止为预约日期与结束时间快照，采用`checkInOpensAt <= now < checkInClosesAt`。例如08:00–10:00场次07:30开放，10:00整截止；推荐开诊前签到，开诊后窗口内仍有效。四场统一公式，历史场次使用实际快照。

共享纯规则放在`VisitRules`，查询使用本次统一`serverTime`，写入口重新采样并校验，同一采样保存签到时间。`AppointmentLifecycleCase`追加`endTime`，只读事实不授予预约写权限。用户列表/详情的`visit`追加开放和截止字段；已确认且已签到/完成也返回窗口，其他预约仍为`visit=null`，医生DTO和REST路径保持。

校验顺序为不存在/归属→预约与就诊状态→开放→截止。状态冲突4502优先于新增的未开放4503和已截止4504；两种时间错误均HTTP409。并发仍由预约与就诊一对一唯一键保证，只保留首次签到时间。

## 兼容与边界

新旧尚未签到的已确认预约均采用新窗口，已成功签到的记录保留，包括旧规则允许的零点签到。医生按归属、确认状态和进度开始/完成，允许超过场次结束或跨日操作。

超时未签到不自动取消、退款、释放库存、删除有效占用或标记爽约。完成接诊不改变预约、资金、库存、快照和序号。无需数据迁移、签到配置、定时任务、迟到队列或人工补签。

实现与边界验收见[就诊设计](../visit/design.md)及[场景覆盖](../testing/scenario-coverage.md#签到窗口)。
