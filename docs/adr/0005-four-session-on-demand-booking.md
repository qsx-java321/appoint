# ADR 0005：四预约场次按需生成并使用统一设置

**状态** 已接受，部分被取代 · **记录日期** 2026-11-05

> 下文保留原决策中的 D+1～D+7、禁止当天创建、创建后十五分钟支付截止和未来二十八项展示。现行日期与截止规则见 [ADR 0007](0007-three-day-booking-and-session-cutoffs.md) 和[业务流程](../business-flow.md#场次设置与库存)。四场、按需生成、统一设置及快照仍适用。

## 背景

旧流程要求管理员为每位医生逐日创建上午、下午排班，并处理开放时间、截止时间、库存调整和停诊关闭。当前业务前提是医院、科室和医生每天正常工作，这些操作增加了不需要的状态和异常分支。

## 决策

每位医生每天固定提供四个预约场次：`MORNING_FIRST`（08:00–10:00）、`MORNING_SECOND`（10:30–12:00）、`AFTERNOON_FIRST`（14:00–16:00）和 `AFTERNOON_SECOND`（16:30–18:00）。每个场次独立维护库存和就诊序号。

管理员只维护一行统一预约设置，字段为每时段容量、挂号费和固定币种 CNY，初始值为 `20 / 10.00 / CNY`。医生未来七日场次采用按需生成：查询 D+1 至 D+7 时，未生成场次用当前设置计算展示值但不写库；首次创建预约时，在同一事务中生成场次、复制设置快照并暂占库存。数据库唯一约束保证 `(doctor_id, appointment_date, session_type)` 最终只有一行。

新预约请求以 `doctorId + appointmentDate + sessionType + patientId` 标识内容，用户不能为当天或 D+7 之后创建新订单。日期窗口在实际占号的条件更新中再次校验。成功订单的支付截止时间固定为创建时间加 15 分钟，允许跨零点；支付时间必须严格早于截止时间。

新流程不提供管理员手工创建、修改、调整或关闭场次的 REST 接口，也不产生停诊取消状态。号源约满、用户取消、超时释放、退款、重复回调和迟到收款补偿仍然保留。

## 历史兼容

原迁移链的 V9 新增统一设置表并扩展 `schedules` 约束。历史 `MORNING`、`AFTERNOON`、空时段、`CLOSED` 和 `CANCELLED_BY_HOSPITAL` 数据继续可读。旧半日场次保持原样，新预约使用四个固定时段。[ADR 0003](0003-unified-schedule-inventory-and-safe-migration.md) 的库存及唯一占用原则和 [ADR 0004](0004-independent-payment-and-reliable-events.md) 的可靠支付事件、退款补偿继续适用。

## 结果

新增医生无需排班即可立即展示未来 28 个预约场次。统一设置变化只影响之后首次生成的场次；已生成场次和订单费用快照保持不变。系统不依赖午夜批处理生成场次，也不再维护医院关门和医生停诊分支。
